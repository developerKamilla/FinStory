# FinStory. Пользовательские сценарии

## UC-01. Начать обучение
Участник: новый пользователь. Предусловие: сервер работает, открыта стартовая страница.
1. Пользователь открывает знакомство и переходит к вопросу об интересах.
2. Перечисляет увлечения свободным текстом.
3. Отвечает на пять вводных вопросов.
4. Видит число правильных ответов и переходит к курсу.
Результат: интересы и результат сохранены в текущем браузере.
Альтернатива: пустой ответ или невыбранный вариант не должен считаться выполненным шагом.

## UC-02. Получить персональный урок
Предусловие: вводный этап завершён; настроены Yandex API и веса.
1. Пользователь выбирает урок.
2. Система показывает ожидание и готовит историю по учебной цели и интересам.
3. Система получает объяснение термина и показывает материал.
4. Пользователь читает историю и объяснение.
Результат: полученный материал сохранён для повторного открытия.
Альтернатива: при неправильной длине система автоматически запрашивает исправление; при окончательной ошибке показывает сообщение и позволяет вернуться к курсу.

## UC-03. Проверить знания
Предусловие: открыт урок.
1. Пользователь нажимает «Проверить себя».
2. Отвечает на три вопроса.
3. Получает число правильных ответов и разбор.
4. Возвращается к курсу.
Результат: урок отмечен как пройденный. Это отметка прохождения теста, а не доказательство усвоения всей темы.

## UC-04. Пройти повторение
Предусловие: пользователь изучил соответствующий блок.
1. Открывает повторение после урока 3, 6 или 9.
2. Отвечает на семь вопросов по блоку, включая короткую задачу.
3. Смотрит результат и правильные ответы.
Результат: пользователь видит, что стоит повторить. Блокировка повторения до прохождения уроков в сценарии не предполагается.

## UC-05. Вернуться к материалу
Предусловие: урок уже подготовлен в этом браузере.
1. Пользователь обновляет страницу или снова открывает урок.
2. Система показывает сохранённый материал и прогресс.
Результат: повторный запрос к генератору не требуется. Одинаковая история в этом сценарии ожидаема.

## UC-06. Изменить интересы
1. Пользователь открывает профиль и начинает опрос заново.
2. Указывает другой набор интересов и проходит вводные вопросы.
3. Открывает урок.
Результат: старые главы, герой и прогресс сброшены; новый материал создаётся для нового ответа.

## UC-07. Проверить подключение перед демонстрацией
Участник: автор проекта.
1. Запускает обычный режим без --demo.
2. Проверяет /api/status: mode равен yandex.
3. Создаёт новый урок с обученным термином.
4. В журнале находит соответствующую историю и источник объяснения.
Результат: источник истории и модель термина подтверждены независимо друг от друга; секреты на экран не выводятся.
