# FinStory. Техническое описание

## Назначение и объём
Веб-прототип предназначен для проверки персонализации уроков финансовой грамотности. Истории создаёт агент Yandex AI Studio; объяснения пяти понятий формирует локально дообученная ruT5. Для остальных понятий работает словарный вариант.

## Компоненты
| Компонент | Файл | Назначение |
|---|---|---|
| HTTP-сервер и связка модулей | app.py | Принимает запросы, собирает урок, проверяет ответы |
| Генератор истории | agent.py | StoryAgent обращается к Yandex; DemoAgent возвращает подготовленную главу |
| Модель терминов | terms.py | TermService загружает веса и формирует объяснение |
| Словарный вариант | baseline_terms.py | Соединяет определение с фрагментом текущей истории |
| Профиль интересов | interests.py | InterestModel вычисляет веса по словам и фрагментам |
| Интерфейс | index.html | Экран знакомства, опрос, уроки, тесты и профиль |
| Учебные данные | data/ | Темы уроков, вопросы и демонстрационные истории |
| Установка весов | setup_model.py | Извлекает подготовленную модель из архива Colab |

## Запрос на урок
Браузер передаёт номер урока, ответ об интересах, героя и предыдущую историю. Сервер находит учебную тему, определения и профиль интересов. StoryAgent получает эти данные и возвращает структурированный JSON. Факты для объяснения фильтруются по наличию слов в истории. Такая проверка отсеивает часть посторонних слов.

TermService получает отдельно каждое понятие, определение, историю и веса. Для обученного понятия создаётся запрос локальной модели. Для необученного возвращаются словарное определение и выбранное предложение истории. Подготовленный урок записывается в журнал и передаётся браузеру.

## Веса и происхождение ответа
Базовая модель: cointegrated/rut5-base-paraphraser. Используется дообучение LoRA с последующим объединением весов. Папка models/terms содержит объединённую модель;

Обученные понятия: дебетовая карта, накопительный счёт, вклад, инвестиция, акция. Встроенный список обученных понятий нельзя расширять простым добавлением названия: нужны данные и отдельная проверка.

## Данные и кэш
Уроки и вопросы хранятся в JSON. Браузер хранит интересы, результат входного теста, героя, главы и прогресс в localStorage. На сервере также есть кэш подготовленных уроков.

Журнал data/generated.jsonl содержит историю, подсказки, веса и объяснения.

## Маршруты
| Маршрут | Метод | Назначение |
|---|---|---|
| /api/status | GET | Режим и backend модели без секретов |
| /api/lessons | GET | Список уроков |
| /api/entry | GET | Пять вводных вопросов |
| /api/interest | POST | Обработка ответа об интересах |
| /api/entry-grade | POST | Результат входного теста |
| /api/lesson | POST | Подготовка урока |
| /api/questions | POST | Вопросы урока или повторения |
| /api/grade | POST | Проверка ответов |

## Обработка ошибок
Для главы задан ориентир 350–500 знаков; проверка допускает 120–650. Если ответ не соответствует ограничениям, выполняются до двух запросов на исправление. После исчерпания попыток возвращается ошибка.

## Условия эксплуатации
Windows, Python 3.11 в окружении alisa-course, браузер, зависимости из requirements.txt. Новая история требует интернета и настроенного Yandex API. Модель терминов может работать на CPU после установки весов. Сервер запускается на 127.0.0.1:8000; это локальный прототип.
