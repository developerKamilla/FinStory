# План проверки FinStory

## Что уже измерено

`model_report.json` содержит долю совпадений с метками на отложенных сочетаниях темы и интереса (для планировщика) и термина и интереса (для терминов). Метки получены из заданных автором правил совместимости. Показатель не измеряет увлекательность, понимание или фактическую точность написанного рассказа. Высокий результат на этих данных не является независимым доказательством качества.

## Слепая оценка текстов

1. Задать `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` на сервере, затем выполнить `python scripts/prepare_review.py --cases 18` из папки проекта. Команда вызывает Alice AI LLM для варианта «агент без плана» и варианта «модели + агент». Третий вариант — прежний шаблон.
2. Раздать копию `blind_review.csv` как минимум двум участникам, не показывая `answer_key.csv`. Каждый заполняет `rater_id` и четыре оценки по шкале 1–5 для всех текстов. Для нескольких оценщиков строки можно скопировать; идентификаторы случаев сохраняются.
3. Финансовые механики дополнительно проверяет человек, знакомый с темой. Если факт неверен, отметить это в `notes`, даже если автоматическая проверка пропустила ошибку.
4. После заполнения запустить `python scripts/summarize_review.py`. Сравнивать средние вместе с примерами ошибок и числом оценщиков.

Шкала: 1 — интерес отсутствует / ошибка / связь глав отсутствует / не хочется читать; 3 — частично; 5 — интерес управляет действием / факты точны / глава логично следует предыдущей / хочется открыть следующую. Для оценки связности лучше давать оценщикам последовательности из двух соседних глав. Оценка одиночной главы не подтверждает связность всей серии.

Одинаковые профили, темы и параметры модели нужны для всех вариантов. Результаты нельзя заполнять предполагаемыми оценками. Автоматический отчёт готов; слепая оценка ждёт реальных читателей и доступа к языковой модели.

## Если используется сам навык в ChatGPT

`python scripts/export_skill_inputs.py` создаёт задания для 12-главных серий. Для каждого профиля есть два задания: только исходные входы навыка и те же входы с планами обученной модели. Запускайте их отдельными обращениями к навыку; для честного сравнения сохраняйте модель и настройки одинаковыми. Перенесите две соседние главы каждого варианта в пустые строки `manual_review_blank.csv`. Не показывайте оценщикам колонку `mode`: перед выдачей замените названия вариантов случайными буквами и сохраните отдельный ключ. Этот ручной путь проверяет именно установленный навык; автоматический путь в приложении использует текст его правил через API.
